# Frame One v0.13A18 — Read-only backup check before replacing data

## Why this exists

Android test APKs from GitHub Actions are still signed with temporary keys
unless the product owner privately provisions the already supported
`FRAMEONE_QA_DEBUG_KEYSTORE_B64` secret. An APK signed with a different
certificate **cannot** be installed as an update; uninstalling the previous
app can delete its local progress, private practice notes and storyboard.

This milestone reduces the chance of replacing saved work using an untested
JSON backup; it does **not** solve the signing-key blocker.

## Implemented

Learn → **Keep a copy of your learning** now offers:
- **Check a backup JSON file**, which opens the local file picker, validates
  the version-one backup using the exact same legacy rules as restore, and
  reports counts for recognized completed lessons, saved notes and storyboard
  shots. It makes **no changes** to the current device's data.
- **Check pasted backup**, for learners using the offline copy/paste fallback,
  with the same count-only result and no storage writes.
- Restore from file and pasted text still use the existing validation,
  original explicit overwrite confirmation and validated rollback logic.
  Confirmation now states the counts that will replace current saved work.
- Invalid or oversized files fail without modifying existing local data.
  Actual text from private notes or storyboard is never shown in the preview,
  logged or uploaded.

A "Checked" status means this JSON is structurally accepted by the existing
restore engine. It is **not** proof that Android's share chooser saved a copy
outside the app, that the backup can be found after uninstall, or that a
future Android update will work in place. These still need verification
on an actual phone.

## Preserved compatibility

- Original backup format: `frameone-learning-backup` version 1.
- Existing `frameone-progress-v01`, `frameone-practice-v07`,
  `frameone-scene-v07` keys and no new localStorage keys.
- All 33 lessons, optional Telugu helpers, 7 Labs and the story plan.
- Android system file-picker route "Restore a backup JSON file" stays intact.
- No new network calls, browser permissions, signing keys or public release.
- The public preview remains v0.12A2 pending a verified upgrade process.

## QA gates

- Source regression tests exercise read-only inspection of actual valid
  legacy backup, unique recognized IDs, unknown entries, note counts and
  invalid storyboard rejection, checking the whole local storage snapshot.
- Real browser QA checks file and pasted JSON inspection, invalid JSON and
  zero mutation, unchanged cancelled restore, explicit confirmed restore,
  note preservation and offline operation.
- Web/TypeScript, seven Lab regressions and Android debug packaging must
  pass before merging this development milestone.

## Owner-only next steps

The existing Windows helper `scripts/setup-frameone-qa-signing.ps1` can
privately create and provision a long-lived **QA debug key**. It must be kept
outside GitHub source code, backed up securely and never sent through chat.
Provisioning still needs the owner to run it on a trusted Windows PC.
Then generate two independent main-branch builds, pass the existing separate
Android package upgrade emulator acceptance and complete real-phone
external backup and restore tests before manually approving publication.
