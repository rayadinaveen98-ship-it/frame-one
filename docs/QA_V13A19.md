# Frame One v0.13A19 — Native Android backup test repaired

## Verified root cause

The v0.13A18 Android full-system backup/restore run (GitHub Actions
[41183154503](https://github.com/rayadinaveen98-ship-it/frame-one/actions/runs/41183154503))
failed **before exporting any backup**. The automation expected the literal
Home-screen text “YOUR WORK STAYS ON THIS DEVICE” and a “Back up” shortcut,
both intentionally removed during the v0.13A16 professional catalog redesign.
It therefore could not reach Learn, and the failure did **not** establish that
the native Filesystem, Share or Android document picker were broken.

## Fix

The Android UI test now validates the cleaner Home has no backup warning,
navigates through the actual bottom **Learn** tab, expands **Keep a copy of
your learning**, checks that **Save / share backup JSON** is present, and
captures both screens before creating real lesson data. The original full
Android test then performs the unchanged user-visible workflow:

1. Write a practice note in a real lesson and complete that lesson.
2. Build a Make Lab three-shot storyboard on screen.
3. Export the exact native JSON via Android Filesystem and Share.
4. Copy those exact app-exported bytes to external Downloads in CI using
   ADB as the **documented destination simulation**.
5. Clear the app's private data and launch with 0/33 completed lessons.
6. Restore the externally held JSON through the **real Android DocumentsUI
   picker** with explicit consent.
7. Verify the completed lesson, practice note and Make Lab storyboard
   appear in the actual Android UI again.

No hidden localStorage injection, synthetic restoration, hand-crafted
backup content, production-signing change or public APK replacement.

## Regression gate

The preflight `tests/test_android_backup_navigation.py` now verifies that
no native QA code navigates by the removed Home card; it verifies both the
new Home/Learn screen evidence and the real save/import assertions exist.
It runs under the web verification job and **before** launching the full
Android emulator, so obsolete UI assumptions fail early and cheaply.

## Release limitations

A green Android emulator test is not proof a physical user saved a JSON
outside the app via the system Share sheet. This CI still uses an ADB
copy for that destination step. It is also **not** proof that APK signing
certificates match across two independently released builds. Secure
persistent QA signing and real-phone upgrade/restore acceptance remain
mandatory before promising seamless installations or publicly publishing
the next stable preview.
